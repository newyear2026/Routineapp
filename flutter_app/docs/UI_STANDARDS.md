# UI Standards

이 문서는 `Routine Timer` 앱의 화면단 표준을 정의한다.

## 1. 색상 표준

- 기본 텍스트는 `AppColors.textPrimary`를 사용한다.
- 보조 텍스트는 `AppColors.textMuted`를 사용한다.
- 주요 CTA는 `AppColors.softAccentGradient`를 사용한다.
- 경고/에러는 장식용 핑크와 구분되는 에러 톤을 사용한다.
- 배경이 파스텔이어도 본문 대비를 우선한다.

기준 파일:
- `lib/theme/app_colors.dart`
- `lib/theme/app_text_styles.dart`
- `lib/theme/app_spacing.dart`

## 2. 버튼 표준

공용 버튼은 `AppButton`을 사용한다.

### Primary
- 용도: 완료, 저장, 시작, 허용
- 스타일: 채워진 그라데이션
- 규칙: 화면당 1개의 주요 행동만 Primary를 사용한다.

### Secondary
- 용도: 보조 확인, 대체 경로
- 스타일: 흰색 서피스 + 보더
- 규칙: Primary와 같은 영역에 배치할 때만 사용한다.

### Ghost
- 용도: 건너뛰기, 나중에, 덜 중요한 이동
- 스타일: 배경 없는 텍스트형 버튼
- 규칙: 파괴적이거나 핵심 행동처럼 보이면 안 된다.

### Destructive
- 용도: 삭제, 초기화, 되돌리기 어려운 행동
- 스타일: 경고성 핑크/로즈 계열 채움
- 규칙: 일반 CTA와 혼동되지 않도록 제한적으로 사용한다.

### 버튼 상태
- `enabled`: 즉시 실행 가능
- `disabled`: 눌릴 수 없는 이유를 근처에서 설명한다
- `loading`: 라벨을 유지하고 로딩 인디케이터를 함께 보여준다
- `destructive`: 되돌리기 어려운 행동 전용

파일:
- `lib/widgets/ds/app_button.dart`

## 3. 입력과 에러 상태 표준

입력 필드는 다음 우선순위를 따른다.

1. 라벨
2. 입력 컨트롤
3. 에러 또는 도움말 메시지

규칙:
- 에러는 스낵바보다 필드 아래 인라인 메시지를 우선한다.
- 저장 실패 안내는 전체 메시지로 보조하되, 원인은 필드 가까이에 남긴다.
- 도움말은 에러가 없을 때만 노출한다.
- 시간, 요일 선택 같은 커스텀 입력도 동일한 규칙을 따른다.
- 입력 상태는 `default / focused / error / disabled` 네 가지를 기본으로 본다.
- 에러 문구는 가능한 한 해결 행동이 바로 떠오르게 짧게 쓴다.
- 플레이스홀더는 설명이 아니라 예시 역할만 맡는다.

파일:
- `lib/widgets/ds/app_labeled_text_field.dart`
- `lib/widgets/ds/app_field_message.dart`
- `lib/widgets/form/pastel_time_field.dart`
- `lib/widgets/form/pastel_weekday_selector.dart`

## 4. UX 우선순위

모든 화면은 아래 순서를 기본으로 한다.

1. 지금 해야 할 핵심 정보
2. 바로 실행 가능한 행동
3. 상태 설명
4. 보조 정보
5. 감성 요소와 장식

세부 규칙:
- 비활성 버튼은 이유를 반드시 함께 보여준다.
- 준비 중 기능은 실제 동작하는 토글처럼 보이면 안 된다.
- 빈 상태에서는 다음 행동을 같이 제시한다.
- 홈 화면에서는 현재 루틴과 액션이 장식보다 먼저 읽혀야 한다.
- 상태는 색상만으로 구분하지 않고 문구나 배지도 함께 사용한다.
- 준비 중 상태는 비상호작용 배지로 표시한다.

## 5. 화면 레이아웃 표준

- 최대 폭은 `AppLayout.maxContentWidth`
- 기본 수평 패딩은 `AppSpacing.screenHorizontal`
- 섹션 간 간격은 `AppSpacing.sectionGap`
- CTA 높이는 기본 `56`
- 터치 타깃 최소 높이는 `44`

## 6. 접근성 표준

- 본문 정보 텍스트는 가능하면 `13` 미만으로 내려가지 않는다.
- 배경이 밝아도 본문과 보조 텍스트는 충분한 대비를 유지한다.
- 아이콘 전용 버튼은 최소 `44x44` 터치 영역을 확보한다.
- 애니메이션은 정보 전달을 방해하지 않는 수준으로 제한한다.
- 색상만으로 상태를 구분하지 말고 문구 또는 아이콘을 함께 사용한다.

## 7. 화면 유형 템플릿

### Home
- 현재 루틴
- 즉시 행동
- 상태 설명
- 하루 흐름
- 감성 요소

### Form
- 입력 목적 설명
- 필수 입력
- 도움말 또는 에러
- 저장 CTA

### Onboarding
- 한 화면 한 메시지
- 시각 예시
- Primary CTA 1개
- Skip은 Ghost

### Settings
- 현재 상태
- 변경 가능한 항목
- 준비 중 항목은 배지로 구분
- 지원/정보 항목은 최하단 배치

## 8. 적용 원칙

- 새 화면은 기존 스타일을 복제하지 말고 공용 토큰과 `AppButton` 기반으로 만든다.
- 동일 역할 버튼이 여러 구현으로 분기되면 공용 위젯으로 통합한다.
- 화면별 감성 차이는 허용하지만, 행동 규칙은 공통이어야 한다.
- 새 상태 표현이 필요하면 화면 내부에서 임시 구현하지 말고 공용 컴포넌트로 먼저 검토한다.
